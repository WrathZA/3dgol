# Persona review — issue #42

**Issue:** feat: choose a starting pattern instead of a random seed
**Branch:** `issue-42-starting-pattern`
**Change type:** new feature / behaviour + data model change → all six personas apply.

## Scope notes

Two departures from the issue as written, both at the operator's direction:

- **The Grid floor moved to 50, not just the default.** The issue left the too-small-Grid case open ("either
  the grid floor guarantees it fits, or the control refuses and says so"). Setting floor = default = 50
  removes the case entirely: no pattern can be too large for any selectable Grid, so there is no refusal
  path, no disabled dropdown entry, and no partial-pattern guard. The cost is that small Grids (down to 16)
  are no longer reachable, and the Grid sliders now start pinned at their minimum.
- **B8 was renamed** from "Restart the run" to "Start a fresh run", because choosing a pattern is not a
  repeat of anything.

## Product — B

Delivers the issue's outcome: the dropdown ships with Gosper's glider gun, Restart reads Random, the default
Grid is 50 × 50, and the three PRD passages the issue reverses are amended rather than deleted. The Actors
reasoning was the delicate one — it defended the single-actor list partly on "nobody chose what you see
first". That survives in narrowed form because a fresh page load still ignores patterns entirely, and the
paragraph now says so instead of being cut.

Beyond the ACs: the Grid floor change removes a capability the Viewer had, and B8 was renamed.

## Technical — B

The pattern list is data with derived helpers, so adding a second pattern is one array entry and no wiring
changes — the AC about extensibility is structural rather than asserted. `largestPatternExtent()` ties the
Grid floor to what is actually shipped, and a test asserts the relationship, so a future oversized pattern
fails the suite rather than reaching a Viewer.

One near-miss worth recording: `panel.ts` was briefly given a *value* import of `PATTERNS`, which would have
falsified its own docblock ("knows nothing about the Simulation"). It is now a type-only import with the
list injected by the composition root, which is where wiring belongs.

Blemish: `RestartRequest` now carries two mutable fields that must be cleared together. It follows the
existing `requested` flag convention, and the loop takes and clears both in one place, but it is two things
to keep in step where there was one.

## QA — C

117 tests, 12 new. The gun is verified as a *working gun* rather than as data — the strongest check available
without a human looking at it:

- Steady population of exactly 56 on the bounded 50 × 50 Grid at Generation 300, still 56 at 600.
- 86 on an effectively unbounded Grid at Generation 300 — exactly 36 (the gun) + 10 gliders × 5 Cells, which
  is period 30 confirmed arithmetically.
- The Explosion dismantles it, making the #30 dependency executable rather than narrative.

**A wrong assumption of mine was caught by its own test.** I asserted all eight reflector-block Cells age
continuously; it failed. A probe showed the gun is correct and that a reflector block is a *catalyst, not a
still life* — the shuttle disturbs each block's inner face every cycle and it reforms, so only the outer
column of each is permanently alive. That corrects the issue's own wording ("blocks whose cells never change
state") and is now recorded in both the test and `src/sim/patterns.ts`. Four Cells reach Maximum Age, not
eight, so the #30 dependency holds by a narrower mechanism than claimed.

The gap is unchanged from #30: no DOM test asserts the dropdown writes into the Restart request, because the
project has no DOM test environment. That is #25's scope and it is open. Layout and hit size are covered by
`pnpm smoke --phone`, which now measures the select.

## Security — A

Reviewed clean, no findings. The pattern list is a compile-time constant; the `<select>` is built with
`createElement` and `textContent`, matching the codebase's existing convention; and `placePattern`'s
typed-array writes are bounded three independent ways (an explicit throw, loop bounds derived from the
pattern itself, and `setAgeAt`'s own `contains()` early return).

The review also surfaced a **correctness** issue it judged unreachable — `Number("")` is `0`, so a change
event carrying the placeholder would resolve to `patterns[0]`. It is reachable by keyboard: arrow keys fire
`change` per selection, so arrowing down to a pattern and back up to the placeholder would silently start a
Run with the first pattern. Fixed rather than accepted.

## Hacker — A

Nothing to work with. The dropdown's entire value domain is generated by the application, the result is
bounds-checked, and the page makes no network requests.

## UX — B

The chooser shares a row with Random, which is honest — both start a fresh Run and differ only in what
Generation 0 holds — and it cost no vertical space at all, so the height problem predicted at planning did
not materialise. The placeholder makes re-selecting the same pattern work, which the issue flagged as a real
trap.

The cost: the Grid floor now equals the default, so both Grid sliders start at their minimum and can only
move up. A Viewer who wants a small Grid cannot have one, and nothing in the interface explains why — the
reason lives in a code comment and the PRD. Acceptable for one shipped pattern; worth revisiting if the
pattern list grows and drags the floor higher.

## Outcome

All grades C or above. Proceeding to squash-merge.
